# Laxyam Academy - codebase audit (2026-10-31)

Read-only audit of every subsystem before the redesign. Status: complete / partial / missing / broken.

## shell

The site shell is a React 19 SPA. js/main.jsx mounts App.jsx: BrowserRouter (basename APP_BASE) > AuthProvider (auth.jsx, mirrors auth.php?action=me and students.php?action=summary) > SiteProvider (components.jsx, useApi('cms.php',{action:'layout'})) > Routes inside <Layout> (layout.jsx). Layout renders, in order: skip link, ScrollToTop, Tracker (track.php beacon), TopBar, Header, <main><Outlet/>, Footer, FloatingActions, Popups and the lazy ChatAssistant (chatbot.jsx). If maintenance is on it renders Maintenance instead. TopBar holds the address, a WhatsApp chip, the phone number, the announcement, LanguageToggle and SocialLinks (lg only). Header is a sticky z-40 bar. It has the desktop nav (xl, 1280px and up), the course MegaMenu, a HeaderSearch panel (courses.php?action=list plus MicButton), a UserMenu, Login and Sign Up, and a plain mobile dropdown nav below 1280px. Footer has the newsletter band (POST enquiries.php?action=newsletter → newsletter_subscribers), 5 link columns, the policy row and the copyright bar.

Everything the shell shows comes from api/cms.php layout_data(), cached for 300s by cache_remember('layout') and cleared by audit_log() whenever an admin saves something. It returns:
- site: from site_settings (is_public)
- social: 7 networks; every social_* URL is empty right now
- nav and footer_links: cms_sections nav_main / nav_footer
- header: cms_sections 'header' merged with defaults
- popups: table popups, which currently has 0 rows
- maintenance, announcement, footer, categories
- mega: course_categories with up to 4 courses each
- footer_courses, chatbot

index.php is the front controller. It applies redirects, then serves dist/index.html with the per-page title, description, canonical, OG tags and JSON-LD, analytics tags and the lx-theme CSS variables. A Google Font is added only when theme_font is Poppins, Roboto, Noto Sans or Mukta.

The live page is the dist build from 12:12. I confirmed in the browser that it loads no web fonts (document.fonts is empty and the CSS has 0 @font-face rules). Its only keyframes are spin, pulse and bounce.

Note: css/style.css and js/components.jsx were changed at 12:50, during this audit, by another implementer. The changes add self-hosted Inter, Plus Jakarta Sans and Caveat via assets/fonts/fonts.css, new tokens and animations, and Simple-Icons-style brand paths plus threads and pinterest. None of this is built into dist yet. layout.jsx, index.php and cms.php were not changed. The findings below describe the live build and layout.jsx as they stand.

### Bugs

- **[high]** `js/layout.jsx:127` - The HeaderSearch form overflows the viewport on common phones (390px and below), creating horizontal page scroll. The wrapper div 'flex flex-1 items-center' has no min-w-0. Its min-content (search icon + type=search input's intrinsic ~187px + EN toggle + mic) plus the 'Search' button is about 380px wide.
  - Evidence: Built-in browser with the search panel open: at 360px, documentElement.scrollWidth was 397 and the Search button spanned x=315-397. At 390px, scrollWidth was 394 (form scrollWidth 378 vs clientWidth 358). At 414px it fits (382 = 382).
  - Fix: Add min-w-0 to the wrapper div (line 127) and size={1} or w-0 to the input. On mobile, make the submit icon-only (<button className="btn-primary px-3"><Icon name="search"/></button>) or hide it below sm (Enter submits). Hide the EN/हिं toggle below sm (MicButton compact).
- **[medium]** `.htaccess:44` - The site sends 'Permissions-Policy: camera=(), microphone=(), geolocation=()' on every page. This disables the microphone for the document, so every MicButton voice-input feature (header search, Courses, Jobs, FAQ, Contact, CareerDetails, chat assistant) cannot work. Users see the mic button and then get 'Microphone permission was denied.'
  - Evidence: Invoke-WebRequest http://localhost:8080/laxyam/ returned that Permissions-Policy header. In the browser, document.featurePolicy.allowsFeature('microphone') === false while window.webkitSpeechRecognition exists, so MicButton renders.
  - Fix: Change it to Permissions-Policy "camera=(), microphone=(self), geolocation=()". If voice search should stay off, hide MicButton when document.featurePolicy?.allowsFeature('microphone') === false.
- **[medium]** `js/layout.jsx:308` - The mega-menu chevron cannot open the menu with a mouse or touch. Hovering the <li> runs showMega (setMega(true)), and the click on the chevron then runs setMega(m => !m), closing it straight away. On touch devices of 1280px and wider (e.g. iPad Pro landscape), a tap fires mouseover and then click, so the chevron never opens the menu.
  - Evidence: In the browser at 1280px: dispatching mouseover on the chevron set aria-expanded='true', and button.click() then set aria-expanded='false' with the [aria-label="Exam categories"] panel gone. A real click in the pane also left the mega menu closed.
  - Fix: Make the button call setMega(true) when the menu was opened by hover within the last ~300ms, or use pointer events: onPointerEnter only when e.pointerType==='mouse', and toggle on click otherwise. Also close on Escape at header level and on outside click.
- **[medium]** `js/layout.jsx:320` - For a logged-in student the header row is wider than 360-375px phones. The logo (shrink-0, 151px) plus search (40) + bell (40) + avatar button (~46) + menu (40) + gaps adds up to ~357px against 328px of space at 360px. The fixed-size buttons cannot shrink, so the row overflows the container.
  - Evidence: Measured in the browser at 360px as a guest: logo <a> 151px, right group 88px (search + menu), container 328px wide with a 16px gap-4. ## home-cms

Earlier versions are kept in cms_revisions (migration-004).

Booleans become checkboxes, a key named 'image' becomes an upload, lists of objects become repeatable fieldsets that use item[0] as the template, and scalar arrays become one-per-line textareas. Only keys already in the stored JSON survive a save, so a new field needs a migration (JSON_SET) to appear. Other editors: list-type data uses includes/admin-crud.php crud() (popups.php, testimonials.php). Page builder: pages.php + includes/blocks.php (block_types/clean_blocks/resolve_blocks) → pages/CustomPage.jsx at /p/:slug; it already has a single YouTube 'video' block. appearance.php writes theme_* settings to site_settings, and index.php injects them as CSS variables.

## courses

Courses and learning is a React SPA talking to PHP JSON APIs. Public catalogue: pages/Courses.jsx calls api/courses.php?action=list, with filters q, category (a parent slug also matches its subcategories), type, language (bilingual is always added), level, price_min/max, sort and page. The response holds items, pagination, facets and stats and is cacheable (Cache-Control public, max-age=60). pages/CourseDetails.jsx calls action=detail&slug, which returns the card fields plus description, outcomes/includes/requirements/faqs (JSON columns), counts, curriculum (sections and lessons with id, title, type, duration and is_preview, never any media paths), instructor, approved reviews, upcoming live classes, related courses and seo. pages/Categories.jsx calls action=categories (fetch_course_categories). Shared presenters and access rules live in includes/catalog.php: COURSE_CARD_COLUMNS, course_effective_price (the only price rule), format_course_card, fetch_course_cards, active_enrolment (expires stale rows lazily), enrol_user, unmet_prerequisite, recalc_course_progress and content_access_allowed. Learning goes through api/lessons.php. action=player (login required) returns the outline with locked/completed flags. action=lesson and action=media go through authorised_lesson(), which enforces access on the server: preview lessons are open even to guests, other lessons need an active enrolment or a staff account, and media streams with Range support. action=progress (POST + CSRF) upserts lesson_progress and recalculates course_enrolments.progress_percent and completed_at. action=enrol-free (POST + CSRF) checks the price is 0 and the prerequisite is met, then calls enrol_user and send_template('enrolment'), which sends in-app plus email. Lesson types in lessons.lesson_type are video, text, pdf, external_video (YouTube/Vimeo only, via embed_url), live and quiz (links to exams.slug through lessons.exam_id). The free-preview flag is lessons.is_preview, and PDF download is controlled by lessons.is_downloadable. The enrol button sends everyone to /checkout/:slug (behind RequireAuth). Checkout.jsx renders FreeEnrol for free courses, and that page goes straight to /learn/:slug with no congratulations screen. MyCourses.jsx uses students.php?action=courses (my_courses, which includes next_lesson_id). The admin pages are declarative crud() configs (includes/admin-crud.php): admin/courses.php (courses), admin/lessons.php (course picker, then Lessons and Sections tabs, with uploads going to private storage), admin/categories.php (one level of parent/sub categories), admin/topics.php (renames or merges the exam_questions.topic text) and admin/resources.php (learning_resources plus resource_categories). Current data: 10 published demo courses with no thumbnails, 14 lessons with no uploaded media (5 marked preview), 1 enrolment, 0 certificates and 0 reviews. All PHP files in this area pass php -l. On a 375px viewport, the course detail page and the catalogue page both scroll sideways.

## tests

Mock tests are one flow, built from a server-scored React SPA and a PHP admin. Public side (js/App.jsx routes): /mock-tests -> pages/MockTests.jsx (category chips + card grid, API action=list); /mock-tests/:slug -> MockTestDetails (action=detail: instructions, attempts, can_start/blocker, Start -> POST action=start); /mock-tests/:slug/attempt/:id -> ExamRoom (action=attempt returns questions and options without answers, saved responses and seconds_left; every click POSTs action=answer {attempt_id, question_id, option_ids[], marked}; Submit -> POST action=submit); /mock-tests/:slug/result/:id -> ExamResult (action=result). /dashboard/tests -> pages/MyTests.jsx (action=mine). api/mock-tests.php does all scoring in finalize_attempt(): it locks the attempt row FOR UPDATE, compares sorted selected ids with the is_correct=1 ids (all-or-nothing, including multiple-correct questions), awards +marks, or -negative_marks when exams.negative_marking=1, writes exam_answers.is_correct/marks_awarded and exam_attempts.score/correct_count/wrong_count/unanswered_count. Deadlines live on the server (exam_attempts.expires_at, 20 s ANSWER_GRACE_SECONDS). Expired attempts are finalised lazily (auto_submitted) by detail, attempt or answer calls. own_attempt() blocks IDOR. Answer key secrecy is enforced: list, detail and attempt never select is_correct or explanation. I confirmed this with live GETs of action=list and action=detail (no is_correct, correct or explanation fields; attempt, result and mine return 401 when logged out). The key reaches the browser only in result_view, and only after submission, when exam_results_visible() is true (result_release immediate/after_end/manual + results_released_at) and show_explanations=1. Result: score ring, pass/fail, correct/wrong/unanswered, percentage, rank among each student's best score, topic breakdown (only when there is more than 1 topic), and a per-question review. Admin: admin/mock-tests.php (crud() config on exams), admin/questions.php (manual question form with 6 option slots, CSV import, topic filter, sync total, questions locked once any attempt exists), admin/topics.php (rename/merge topics), admin/leaderboard.php (best attempt per student, CSV), reports.php?tab=tests (aggregates + distribution). Tables: exams, exam_questions (topic added in migration-005), exam_options, exam_attempts (question_order JSON for shuffle), exam_answers (UNIQUE attempt_id+question_id). There is no separate quiz engine: lessons.lesson_type='quiz' only links to a mock test (LessonPlayer 'Open Practice Test'), and the 'Daily Quiz' resource category holds file/link resources. Live DB has 3 demo exams (ids 1-3, 10 questions, no topics, 0 attempts).
